# Desktop

How the Hyprland desktop on `perry` is put together and why the tools were chosen. How it looks is described in [STYLE.md](STYLE.md).

## Hyprland

- The config is `.config/hypr/hyprland.lua`, in Lua (not the old hyprlang `.conf` format). It is a plain dotfile. Values that the NixOS config also knows (monitors, keyboard layout, theme colors) come from a file generated by home-manager, see STYLE.md.
- Hyprland's Lua API is new and little documented. Verify functions and arguments against the Hyprland source (`src/config/lua/bindings/`) or its example config instead of guessing from hyprlang syntax.
- `make test` in `.config/hypr` checks the config (on `perry`). Autoreload is disabled; reload with `mod + SHIFT + r` or `hyprctl reload`.
- greetd starts Hyprland directly on boot, without a login screen. This is intended.

## Keybindings

Navigation follows vim keys. The scheme (which modifier means what) is documented in a comment block in `hyprland.lua`, next to the binds themselves; keep new binds consistent with it. Single letters with `mod` launch programs.

## Desktop tools

Each topic has its own NixOS module (`nix/modules/network.nix`, `bluetooth.nix`, `sound.nix`); the module's comments name the tool and how it is opened.

- **Wi-Fi/LAN:** NetworkManager with wpa_supplicant. Switching to iwd was considered and rejected: large change, risky for enterprise Wi-Fi. `networkmanager_dmenu` (a rofi menu) connects; `nm-connection-editor` (opened from that menu) adds, edits and deletes saved networks. NetworkManager prefers LAN automatically.
- **Bluetooth:** BlueZ with `blueman-manager`. The tray applet is not used.
- **Sound:** PipeWire (with PulseAudio compatibility) with `pavucontrol`. `pwvucontrol` was considered; pavucontrol was chosen for robustness and easy GTK3 theming.
- **Status bar:** waybar, slim and floating at the top. The main monitor shows workspaces, clock and system status; clicking the network, Bluetooth or sound icon opens the tool above, and the palette icon switches the theme (see STYLE.md). The left monitor shows workspaces only. No tray; add the `tray` module only if a tool really needs it. Config in `nix/modules/home/waybar.nix`, design details in STYLE.md.
- **Pokémon in the bar (prototype, branch `waybar-pokemon`):** little Pokémon walk around next to the workspaces. Click: choose one to spawn, middle click: a random one, right click: choose one to despawn, scroll up: drop a berry for them to race for; `waybar-pokemon --help` in a terminal. The program lives in `nix/packages/waybar-pokemon/` (own README, meant to become its own repository), its integration in `nix/modules/home/waybar-pokemon.nix`; Hyprland starts its daemon.
- **Launcher:** rofi.
- **Logout menu:** wlogout, through `bin/wlogout-once.sh`, which toggles it.
- **Wallpapers:** awww shows them; the files are in `~/Media/Wallpaper` (`WALLPAPER_HOME` in `hyprland.lua`). `mod + w` opens a rofi grid with a preview of every wallpaper (type to filter by name, the current one is preselected); `mod + CTRL + w` cycles to the next one. Both are `bin/wallpaper.sh`. Rofi would load every full-size image and may not read webp, so the script creates small thumbnails with libvips (`vipsthumbnail`, fast and reads jpg, png and webp) in `~/.cache/pb_wallpaper_thumbnails`. They are created on the first use and again for new or changed wallpapers; thumbnails of deleted wallpapers are removed automatically. The grid (columns, rows, preview size) is set by the variables at the top of the script.
  - **The previews are square (smart-cropped), on purpose.** Rofi reserves a square box for each preview before the image is loaded, and draws the image scaled by the smaller of (tile width / image width) and (box height / image height). For a square image of exactly the box size that is exactly 1, so it is shown pixel for pixel. A 16:9 preview was enlarged by about 0.6% and looked blurry, and the box left an empty gap below it; no setting fixes that, since it depends on the tile width. Do not change the previews to another shape without checking sharpness on screen.
  - **Whole-pixel placement:** the preview is aligned to the top left, as a centered image sits on half a pixel, which cairo smooths. The window is a few pixels wider than the tiles need; if it were narrower, rofi would shrink the previews, which blurs them too.
- **Screenshots:** `mod + SHIFT + p` runs `bin/screenshot.sh`: the screen freezes (wayfreeze), you drag a region (slurp), it is captured (grim) and opens in swappy for annotating, copying or saving. Escape cancels. The tools are installed in `nix/modules/desktop/hyprland.nix`. The freeze is needed, since slurp and grim alone do not stop videos while you select.
- **Files:** Thunar, mounting via udisks and gvfs (`nix/modules/files.nix`).

## Default programs

Which program opens which file type is defined in one place: `openWith` in `nix/modules/files.nix`. It is grouped by program (its `.desktop` entry) and lists the file types (MIME types) each one opens.

- **It follows the XDG standard** (`mimeapps.list`): NixOS writes the defaults system-wide. Thunar, Firefox, kitty (clicked links), `xdg-open` and `pb-open` use them. Ranger follows them too, through a rule at the top of `.config/ranger/rifle.conf` that hands files to `xdg-open` (only where `xdg-open` exists, so not on macOS). Emacs opens files itself and is not affected.
- **Defaults are per file type, not per extension.** Many source code types count as plain text, so `text/plain` covers them, unless a more specific type has its own entry.
- **Adding a type:** run `pb-mime <file>` (in `zsh/files.zsh`). It prints the file's type and its current default program. Add the type to the program's list in `openWith` and rebuild. Each type may appear only once; the rebuild stops with a message otherwise.
- **Personal choices win:** "Open with... / set as default" in Thunar writes to `~/.config/mimeapps.list`, which overrides the system-wide defaults. Delete the entry there to return to the Nix default.
